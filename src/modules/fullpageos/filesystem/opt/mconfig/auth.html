The pi account is used for SSH, console login and sudo. Its password is separate from the web password and touchscreen PIN. Existing SSH keys will keep working.

The factory default is raspberry. If it has been changed, use the current password instead.

How do I test SSH access?
  1. On a computer on the same network, open Terminal (macOS/Linux) or PowerShell (Windows).
  2. Run ssh pi@PRINTER_ADDRESS, using the printer's network address, not localhost.
  3. On a first connection, verify the host-key fingerprint through a trusted channel before accepting it.
  4. Sign in as pi using its current password. Nothing appears while you type the password; this is normal.
  5. Keep the working session open until setup is complete. Type exit when you are ready to close it.

SSH is a text-based maintenance connection, not the printer's browser interface. A browser cannot test an SSH login for you. If login fails or you do not know the current password, contact your printer administrator before enabling Lockdown.

Why does my browser show a certificate warning?

This printer generates its own HTTPS certificate. The connection is encrypted, but your browser does not automatically trust the printer's identity. The warning is separate from whether password protection is enabled.

Verify that you are connecting to your actual printer, and verify its certificate fingerprint through a trusted channel before trusting the certificate on your device. Do not ignore a changed certificate unexpectedly. Ask your administrator for help if you are unsure.

Remote security settings always use HTTPS to keep passwords encrypted. With protection Off, ordinary interface browsing can still use HTTP; HTTP is not encrypted.
